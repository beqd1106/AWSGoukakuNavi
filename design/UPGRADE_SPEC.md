# AWSnote 問題アップグレード仕様（解説の厚み＋選択肢の長さ）

## 直したいこと
1. **解説が答えの言い換えで終わっている**（1250問／全体の7割超・平均45字）。これでは覚えられない。
2. **正解だけがわずかに長い癖**（正解が単独最長 52%・理想25%）。長さが手がかりになってしまう。

## 入力
`design/up/<ID>.json` … 配列。各要素：
- `id` / `question` / `choices`（4つ）/ `correctIndex`（複数正解のときは `correctIndexes`）
- `explanation`（現状の解説）/ `wrongChoiceExplanations` / `service` / `domain` / `beginnerNote`
- `needExplanation`（true なら解説を厚くする）/ `needBalance`（true なら長さをそろえる）

## やること

### A. 解説を書き直す（needExplanation が true のもの）
**100〜200字**で、次の3つを含める。
1. **結論** … なぜそれが正解か。
2. **中身** … そのサービス／概念が何をするものか、具体的に一言。
3. **区別のポイント** … 混同しやすい隣のサービスとの線引き。
   （例：「サブネット単位・ステートレスなネットワークACLとは異なり、〜」）
   **ここが試験で問われる核心**なので必ず入れる。

### B. 選択肢の長さをそろえる（needBalance が true のもの）
**正解が単独で最長にならないようにする。** 正解を刈り込むか、誤答に具体を足す。
4つの長さの差は小さいほどよい（目安は最長と最短の差が15字以内）。

## 絶対に守ること（AWSは情報が変わるので特に厳しく）
- **具体的な数値を新たに書かない。** 料金、無料利用枠の量、SLAのパーセンテージ、
  応答時間、リージョン数、上限値などは、**すでに設問・選択肢・現在の解説に出ている場合のみ**
  そのまま使ってよい。自分の記憶から新しい数値を持ち込むのは禁止。
- **サービス名は正式名称で正確に。** 通称や古い名称、存在しないサービス名を書かない。
  自信がないサービスには触れない。
- **正解は正解のまま、誤答は誤答のまま。** 正誤関係と `correctIndex` を変えない。
- 誤答を肉付けするとき、**うっかり正しい記述にしない**。実在するが、この問いの答えではない内容にする。
- 出題範囲は **AWS Certified Cloud Practitioner（CLF-C02）**。
  アソシエイト以上の深い内容や、実務寄りの細かい設定には踏み込まない。
- 設問文（question）は変更しない。
- 絵文字は使わない。

## 迷ったら
確信が持てないことは書かない。短くても正しい解説のほうが、詳しくても怪しい解説よりよい。
その場合は `note` に「根拠が薄いので踏み込まなかった」と書く。

## 出力
`design/up_out/<ID>.json` に JSON配列（UTF-8）。**入力の全件**を次の形で：
```json
{
  "id": "q-tec-021",
  "explanation": "書き直した解説（needExplanationがfalseなら入力のまま）",
  "choices": ["…","…","…","…"],
  "note": "迷った場合だけ1行"
}
```
`choices` は必ず4つ、順序は入力と同じ。

**中断対策（厳守）**：サブエージェントを起動しないこと。
**20問ごとに必ず出力ファイルへ書き出す**（20→40→…と上書き）。最後にまとめて書き出すのは禁止。
